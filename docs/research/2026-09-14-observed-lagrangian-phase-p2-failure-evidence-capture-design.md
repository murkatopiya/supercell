## B. Strategy comparison

All strategies require the external original-input/authority envelope. “Can” below means with constrained implementation and review, not an unconditional claim about arbitrary callbacks or hostile objects.

| Strategy | Operation order / decisions / successful shape | Deterministic exact evidence; pre-provider geometry | Algorithm duplication / tests / overhead / semantic risk |
|---|---|---|---|
| 1. External wrapper/recorder only | Can preserve all three if it calls once | Can record inputs/returns/call order, cannot observe private crossing or arithmetic state | Low overhead and risk, easy boundary tests; insufficient. Replaying partition/quadrature in harness is rejected |
| 2. Add diagnostic trace to primitive results | Arithmetic/decisions can stay fixed; success shape changes if trace added there | Captures geometry and local states; needs propagation at every layer | No algorithm copy; straightforward tests; allocation on traced paths; moderate propagation risk. Failure-only variant avoids success-shape change but does not retain successful sibling work subsequently discarded |
| 3. Optional observer/sink callback | Arbitrary user callback can throw, mutate or reenter and alter behavior | Can see geometry, but caller behavior can destroy determinism | No duplication; exception/reentrancy burden and call overhead; reject user callbacks in numerical execution |
| 4. Structured failure carrying partial trace | Success shape can stay fixed; status/code/operation preserved additively | Good for typed failures, but must collect context before stack unwind; upstream spreads/clones can lose or overwrite trace | No duplication; awkward overlap with existing exposure/history `trace`; larger failure API/propagation changes; cannot alone preserve later successful sibling calls |
| 5. Qualification API using same algorithm with private context | Existing scientific result remains exact; only capture API returns separate metadata | Complete generated geometry/arithmetic prefix, deterministic under pure-data/provider contract | No numerical duplication; explicit context threading plus private journal; linear trace storage, moderate instrumentation-review risk |

**Choose strategy 5, implemented with an opaque optional context and private journal, not an observer callback.** The extra facade is thin invocation/snapshot plumbing. It does not construct crossings, interpolate, integrate, sum, compare, recover, or select anything itself. No fallback strategy may reimplement those operations in a harness.

## C. Preferred boundary and exact observational-invariance argument

Introduce a generic capture module below the estimators, independent of the qualification codec and controller. A context is an opaque library-issued token; a module-private WeakMap owns journal state. Public callers cannot supply a sink function, override append methods, inspect a live journal, or obtain references to scientific data through it. Existing entry points accept a trailing optional context; the qualification facade supplies it, calls the existing operation once and retrieves a detached frozen journal afterward. Existing return unions, result objects, enumerable properties, schemas and controller seals do not acquire capture fields.

Each invocation has a sequential call ID, parent ID and explicit scope (role/step/interval/requirement where known). Token creation is per synchronous capture invocation; no global active-recorder variable, async-local mechanism or provider-lifetime mutable recorder. Thread the token through nested calls and optional provider method arguments. For standalone accumulator capture, the context belongs to that accumulator invocation/stream and is not reused after closure. Providers created earlier receive the current token at query time; do not bind a stale construction token into a long-lived provider closure. Uninstrumented custom provider methods may ignore extra arguments: record their actual call/return externally, but mark unavailable private adapter evidence rather than certify it.

Journal events record a finite set of operation sites and their existing local variables: ENTER, completed computation, candidate generated/accepted, provider call begin/return/throw, accumulator attempted/committed, rejection and EXIT. These are symbolic source sites, not wall-clock timestamps. Record accepted nodes once in chronological order and append deltas rather than repeatedly cloning the whole prefix. Retain original full boundary indices once, generated candidates as visited, and the exact failed candidate before return. A child rejection is linked to its caller; do not overwrite it when the caller maps the public operation to `partition/duration-bound` or `ESTIMATOR_INCOMPLETE`.

The invariant to prove in implementation review is projection equivalence: erase journal operations and the optional context plumbing from the new execution, and the remaining scientific operations, values, branches, provider calls and return structure must equal checkpoint `52a9fcc`. Apply it inductively at each source site:

1. Copy an already evaluated primitive value into recorder-owned storage. Do not repeat the numerical expression to record it. Where a value is passed directly into `finite`, capture its existing argument before that guard throws. Naming an inline result is allowed only at the identical evaluation point with identical operand order and binary64 rounding; no algebraic refactor.
2. Keep every scientific condition and short-circuit intact. Recording may branch on capture enabled, but never feeds values into scientific predicates. Do not evaluate skipped guard operands just to provide a richer explanation. Persist the rejected compound check site and available operands; label unexecuted predicates unavailable.
3. Do not sort, snap, merge, deduplicate, truncate or add geometry. Partition enumeration remains increasing height then reverse for downward travel. History event ordering and exact-time merging remain the existing rules. Record the pending common-event insertions before sorted `nodes` exists; their journal order is execution order, not a substitute scientific union.
4. Provider attempts remain exactly where they are. Partition start failure still prevents the end call. Controller pointwise code computes **both** coarse `a` and fine `b` before testing `a.status`; retain both calls even if coarse fails. Its exposure `.map` constructs all selected partitions before integration tests rejection; do not short-circuit it. History calls native partitions and own-path foreign-node evaluations exactly as before. Ordinary oracle remains conditional on explicit success.
5. Preserve Neumaier assignment/commit sequence and sticky failures. Record s/c before attempted add and each available local; never call `add` or `total` for diagnostics. Distinguish contribution generated, signed committed and absolute committed. Preserve eager computations such as partition `total` and `bound`, even when the first fails.
6. Existing success construction and failure construction are untouched in shape and numeric content. Facade returns `{result, capture}`; its `result` is the actual existing result, not a serialized clone or reconstructed object. For provider-function results test structure/topology and behavior, not cross-run function reference equality. Internal controller preparation/plan/assessment objects remain the actual sealed objects.
7. Recorder data never influences authority, eligibility, support, tolerance, dt, candidate order, duration or outcome. No hidden retry or recovery. Capture enabled cannot turn unsupported into zero, a failed estimate into COMPLETE, or a completed INVALID CONTROL check into arithmetic failure.

This is a design-level invariance proof obligation, not a claim of tested implementation. It applies to ordinary synchronous execution with supported plain input data and the reviewed immutable/pure provider contract, under the pinned binary64/runtime assumptions. Extra allocation affects runtime and memory use; no in-process mechanism can guarantee survival of process termination or out-of-memory. Resource failure yields incomplete capture, never silently complete evidence or altered scientific results. This limitation is already compatible with frozen §3 resource-incompleteness policy, not a scientific specification conflict.

## D. Failure trace contract

### Internal capture object

Proposed identity `p2-failure-capture/v1` is a design proposal, not a frozen artifact schema. Store recorder-owned plain data only. Internal number slots retain actual binary64 values, including nonfinite values; no canonical JSON validation in primitives. Private arithmetic BigInt state, when needed for scaled rounding, uses explicitly typed decimal/hex strings for integer bits/exponents; it is not a binary64 sentinel.

Required internal contents:

- Capture/schema version, operation invocation tree, ordered sequence IDs, entry/exit/rejection sites, exact public result classification, and original invocation data snapshot or external snapshot reference.
- Provider/path fingerprints if they existed, otherwise explicit NOT_CREATED; evaluator identity/version and declared recipe reference separately. Never fabricate the fingerprint of a rejected path/topology.
- Role, accepted-step index, vertex identity, local subinterval index, stream name, controller requirement/run/candidate identity where available. Not applicable fields have explicit applicability; unknown fields have an availability reason.
- Original topology and support; ordered candidate boundary IDs/heights, visited candidate index, generated lambda/time/position, accepted partial nodes, previous node, step endpoint constraints, d/dy/direction. Unvisited candidates retain boundary identity but have no generated time/position.
- Current left/right endpoints, segment/side/support context; attempted query position/time; call entered/completed/threw flags; raw returned adapter operands when obtained, including rejected nonfinite values; existing successful operands and complete subintervals.
- Arithmetic operation/stream, operands and evaluated intermediates, contribution order, accumulator state before attempt and committed state afterward where reached. Track s and c separately, with partial meaning. Do not compute an extra corrected total. Record available raw total, bound and normalization values even when a later check fails.
- History partial common insertions/native interval references/cursors, ordered final nodes when assigned, evaluated roles/sides and partially completed local history/reference work; comparison/controller prefix checks and available intermediate state.
- Last completed **instrumented operation site** with call/sequence ID, pending/failing site and nested cause. Initial rejection uses NONE_REACHED. This is not a claim to record every JavaScript VM instruction or inaccessible operation inside a custom evaluator.
- Counts by ordinary method, explicit method, underlying evaluator and oracle, scoped without double-counting nested calls. `anyProviderCall` means any ordinary/explicit call; `anyEvaluatorCall` is separate. Creation-time profile identity sampling is a separate category. Derive totals from actual begin/return events, never extra evaluations.
- `traceCoverage: COMPLETE_GENERATED_PREFIX | PARTIAL | INCOMPLETE`, explicit missing sites/reasons, and terminal disposition (returned rejection, complete result, escaped exception, interrupted). A complete generated prefix of a failed estimate is not a complete scientific estimate.

At a first collapsed crossing, record start node and the failing candidate; the endpoint node has not yet been pushed and must not be described as accepted. At a second collapsed crossing, the first internal node is accepted and the second is only generated. At history failure before `nodes` assignment, preserve common-map insertions explicitly instead of claiming the scientific `nodes` array was populated. At scaled product exponent overflow, the offending exponent/product are available but a final infinite product may never have been formed: record the overflow condition, not an invented Infinity.

## E. Malformed and nonfinite capture rules

At the future qualification facade, encode the declared data input with `encodeRejectedInput` **before** ordinary canonical validation, provider/path construction, normalization, cloning that might reject it, or fingerprint JSON. This includes nonfinite/negative-zero accepted times/positions, duplicate/nonordered/nonfinite heights, sparse vertices/knots/support/step/sample arrays, undefined entries or missing own properties, malformed requests/intervals/contexts, nonfinite local integral operands, and prepared partitions/comparisons containing nonfinite diagnostic values. Duplicate knots are ordinary finite JSON but must still be retained before any normalization. Preserve absent property versus own undefined versus hole versus null.

Do not serialize options containing `evaluate`/`ordinaryOracle` as a lossless data object. Capture their explicit artificial recipe and version separately, and capture the plain data portion before the factory's `JSON.stringify` identity step. Source/Analysis inputs require the already-declared artificial profile data and gradient parameters; obtaining a snapshot must not add profile sampling calls to the numerical invocation. Record only actual factory calls if they are part of existing behavior.

Raw rejected provider results and nonfinite computed coordinates/intermediates are captured at the source site, then tagged at export using the same codec's binary64 representation. This is the rejected-value data channel, not an ordinary numeric result field. NaN/Infinity/holes/undefined never become null. Preserve NaN bits only as exposed by the runtime; do not promise original hardware payload preservation beyond it. Retain negative-zero bits in forensic tagged values while leaving the scientific signed-zero rules unchanged.

The approved codec rejects functions, symbols, cycles, accessors, hidden/extra properties and unsupported object prototypes. It rejects accessors without invoking them. Do not broaden that contract in this implementation. Proxy traps cannot be safely neutralized by generic JavaScript reflection; qualification recipes must be trusted plain data, not arbitrary proxies. For unencodable input record a capture-contract error and INCOMPLETE evidence without substituting a fake scientific rejection. Existing APIs' escaped exceptions remain escaped. Do not stringify arbitrary thrown objects or access their getters/stack while numerical code is running. For caught provider exceptions retain occurrence/site and any safely available declared error identity; stack text is not required deterministic evidence.

## F. Determinism and side effects

Capture helpers accept only module-owned records, copied scalars and explicitly copied supported arrays/records. Freeze detached capture copies, never caller objects. Do not recursively traverse provider objects or callbacks. Do not introduce new property access on arbitrary caller objects just to explain a guard. Input capture belongs outside numerical execution and uses the approved plain-data codec; inside, retain values already read by the algorithm. Existing scientific snapshots/freezes remain exactly as reviewed.

Deterministic IDs are invocation-local counters and explicit scope paths; no randomness, clock, stack address, filesystem path, locale sorting or object insertion order. Object entries in exported snapshots are canonicalized; scientific arrays and journal events are never sorted for convenience. Keep simultaneous history event ordering exactly as in `eventOrder`, and distinguish generated insertion order from final sorted union order.

The generic journal imports no filesystem, crypto, process environment, observed loader, profile parser, Simulation, controller, P/E1/H harness, registry or campaign. Qualification export may import the existing pure codec; estimators must not import `p2Qualification`. Providers retain their reviewed production diagnostic dependencies, but instrumentation introduces none. Static dependency tests must distinguish existing provider physics imports from forbidden new observed/campaign dependencies.

No caller callback runs on append; nothing can reenter from a sink. Context state is private and per invocation, so nested library calls get explicit parents and concurrent independent captures cannot mix. Recoverable recorder faults must disable/mark capture incomplete in recorder-owned state without throwing into an existing scientific catch or changing its return. Final export errors occur after the scientific call and cannot rewrite its result. No silent event cap/ring buffer is acceptable for §14 evidence. Fatal process/resource errors cannot be made transparent; report interrupted/incomplete work when evidence survives.

Runtime cost with capture disabled is context checks/plumbing only, with payload allocation guarded off. With capture enabled cost is linear in retained operations/inputs and generated trace size; use append events instead of quadratic repeated prefix snapshots. Wall-time/GC/JIT equivalence is not promised. Binary64 values and provider calls are the required invariants. An impure provider reading time or mutable external state already violates the reviewed provider contract and cannot gain qualification validity through capture.
